Настройки логов ​

В Options → Logs собраны настройки вкладки Logs. Изменения применяются сразу.

Search Settings ​

Режимы поиска вкладки Logs по умолчанию:

ПараметрГде ищет
Search by event nameЗаголовок, компонент, стор, URL (включён по умолчанию)
Search by keyКлючи в данных события и пути изменений
Search by valueЗначения в данных события

Ignore list ​

Группы событий, добавленные через Ignore во вкладке Logs. События этих групп не записываются.

КолонкаСодержимое
TypeТип события
EventКлюч группы: запрос (метод и путь), компонент, стор и т.д.
AddedДата добавления правила
  • Log again в меню строки снимает одно правило.
  • Log all again снимает все правила.

Тот же список доступен через индикатор ignored на панели вкладки Logs.

Logs and limits ​

Logged events ​

У каждой группы есть чекбокс: снятая группа не логируется совсем, уже записанные события остаются. По умолчанию включены все группы.

ГруппаСобытия
NetworkSend request и Receive response
Props changesChange props
EmitsEmit
Pinia changesChange store (после повторной отметки стор начинается с нового Store snapshot)
Store actionsStore action
NavigationNavigation
JS errorsJS error

Число рядом с чекбоксом показывает, сколько событий группы хранится сейчас.

Data size ​

ПараметрПо умолчаниюДиапазонНазначение
Memory budget20 МБ8 – 1024 МБОбщий объём всех событий в буфере (приблизительный размер после сериализации). Сетевая запись, общая для запроса и ответа, и одинаковые тела учитываются один раз. Бинарный ответ учитывается как формат и размер, без самого файла
Limit event sizeвыкл.—Выключено: события хранятся целиком и ничего не обрезается, поэтому экспортированный отчёт содержит полные данные
Max event size512 КБ16 – 16 384 КБТолько при включённом Limit event size: крупные части события (снимки стора, аргументы, результаты) отбрасываются, сетевые тела обрезаются до этого размера

При достижении бюджета памяти журнал отсекается по Navigation, и каждое событие до неё удаляется. Изменения Pinia до этой точки собираются в Store checkpoint, поэтому у оставшихся изменений сохраняются Before / After; предыдущая база и diff, из которых она собрана, удаляются (см. Как хранятся события). Последняя навигация переписывается в снимок страницы, а если журнал всё ещё больше бюджета, удаляются самые старые из оставшихся событий. Самое новое событие сохраняется всегда, даже если одно превышает бюджет. Send request и Receive response дополнительно ограничены лимитом Maximum HTTP requests — тем же кольцом, что HTTP-строки вкладки Network (Options → Network, по умолчанию 500): запрос и его ответ уходят вместе. События WebSocket ограничены лимитом Maximum WebSocket events (по умолчанию 500): open, sent, received и closed считаются по одному.

Полоса под полями показывает текущее использование (Used X of Y); выше 90 % она становится оранжевой.

Значения вне диапазона приводятся к ближайшей границе. Defaults восстанавливает все настройки блока.

Data masking ​

Значения маскируются в момент записи события, поэтому не попадают ни в интерфейс Logs, ни в экспорт.

ПараметрНазначение
Mask sensitive dataВключает маскирование (включено по умолчанию)
Mask token-like values in any textМаскирует JWT, учётные данные Bearer / Basic и номера карт внутри любой строки
Список Key containsКлючи объектов, имена заголовков и параметров, содержащие эти фрагменты, маскируются

Ключи по умолчанию: password, passwd, pwd, secret, token, authorization, cookie, apikey, sessionid, privatekey, creditcard, cardnumber, cvv, cvc, ssn, otp.

Сравнение ключей не учитывает регистр и разделители (api_key, api-key и apiKey — одно и то же). Фрагменты из 4 букв и короче должны совпадать с целым словом, поэтому pwd или otp не маскируют посторонние ключи.

Свои фрагменты добавляются в поле под списком, удаляются через меню строки. Default keys восстанавливает список по умолчанию.

Замаскированные значения заменяются метками: [MASKED] — для значений чувствительных ключей, [MASKED JWT] и [MASKED CARD] — для токенов и номеров карт, найденных в тексте (номера карт проверяются алгоритмом Луна).
