Настройки логов ​

В Options → Logs собраны настройки вкладки Logs. Блоки идут так: Search Settings, Logs and limits, Ignore list, Data masking, Export. Изменения применяются сразу.

Search Settings ​

ФлажокПо умолчанию
Search by event name (title, component, store, URL)включён
Search by key (payload keys and changed paths)выключен
Search by value (payload values)выключен

Как запрос совпадает, описано в Работе с логами. Если key и value оба выключены, поиск по имени всё равно работает.

Logs and limits ​

Logged events ​

У каждой группы есть чекбокс: снятая группа не логируется совсем, уже записанные события остаются. По умолчанию включены все группы.

ГруппаСобытия
RequestsSend request и Receive response
WebSocketWebSocket open, WebSocket sent, WebSocket received и WebSocket closed
Props changesChange props
EmitsEmit
Pinia changesChange store (после повторной отметки стор начинается с нового Store snapshot)
Store actionsStore action
NavigationNavigation
ClicksClick
JS errorsJS error

Число рядом с чекбоксом — сколько событий этой группы хранится сейчас. Подсказка: Currently stored. Requests не считает Receive response, единица — requests. У остальных групп единица events.

Data size ​

ПараметрПо умолчаниюДиапазонНазначение
Memory budget20 МБ8 – 1024 МБОбщий объём всех событий в буфере (приблизительный размер после сериализации). Сетевая запись, общая для запроса и ответа, и одинаковые тела учитываются один раз. Бинарный ответ учитывается как формат и размер, без самого файла
Limit event sizeвкл.—Включён по умолчанию. Выключено: события хранятся целиком. Поле Max event size видно только пока флажок включён
Max event size512 КБ16 – 16 384 КБКрупные части события (снимки стора, аргументы, результаты) отбрасываются, сетевые тела обрезаются до этого размера

При достижении бюджета памяти журнал отсекается по Navigation, и каждое событие до неё удаляется. Изменения Pinia до этой точки собираются в Store checkpoint, поэтому у оставшихся изменений сохраняются Before / After; предыдущая база и diff, из которых она собрана, удаляются (см. Как хранятся события). Последняя навигация переписывается в снимок страницы, а если журнал всё ещё больше бюджета, удаляются самые старые из оставшихся событий. Самое новое событие сохраняется всегда, даже если одно превышает бюджет. Send request и Receive response дополнительно ограничены лимитом Maximum HTTP requests — тем же кольцом, что HTTP-строки вкладки Network (Options → Network, по умолчанию 500): запрос и его ответ уходят вместе. События WebSocket ограничены лимитом Maximum WebSocket events (по умолчанию 500): open, sent, received и closed считаются по одному.

Строка под полосой: Used {size} of {size} (approximate serialized size). Полоса становится оранжевой с 90 %.

Число вне диапазона округляется и прижимается к ближайшей границе. Нечисловое значение сбрасывается на значение по умолчанию. Пустое поле считается нулём и поэтому становится минимумом (8 МБ или 16 КБ). Новое значение применяется, когда поле подтверждают.

Defaults в этом блоке возвращает флажки групп, бюджет, Limit event size и Max event size. Поиск, список игнорирования, маскирование и Compress report он не сбрасывает.

Ignore list ​

Группы событий, исключённые из записи. Группа — один объект: один и тот же запрос (метод и путь), один и тот же компонент, один и тот же стор и т.д. События игнорируемых групп не записываются вовсе.

Под заголовком: These event groups are not recorded. Log again resumes one group.

СтолбецНазначение
TypeПодпись события (Send request, Change store, JS error и остальные)
ObjectСохранённый ключ группы: URL, компонент, стор, сообщение и т.д.

Меню строки — только Log again. Log all again напротив заголовка очищает список и недоступна, когда он пуст. Пустая таблица: No ignored objects. Клик по строке ничего не делает. Карточки деталей нет.

Индикатор ignored на панели вкладки Logs открывает эту таблицу. При пустом списке он скрыт.

Data masking ​

Значения маскируются в момент записи события, поэтому не попадают ни в интерфейс Logs, ни в экспорт.

Под заголовком: Values are masked when an event is captured, so they never reach the Logs view or exports.

Оба флажка подписаны Mask sensitive data.

  • Первый включает маскирование. По умолчанию он включён. Пока он выключен, список ключей приглушён, и записанные значения сохраняются как есть.
  • Второй стоит сразу под ним и недоступен, пока первый выключен. По умолчанию он включён. В любом тексте от 8 символов он маскирует JWT ([MASKED JWT]), учётные данные Bearer / Basic / Token (Bearer [MASKED]) и номера карт ([MASKED CARD]). Отдельной подписи у этого поведения нет.

Заголовок списка ключей — Key contains. Пустая таблица: No keys — only value patterns are masked. Подсказка поля: Key fragment, e.g. accessCode. Add или Enter обрезает фрагмент. Пустое значение: Key cannot be empty. Тот же фрагмент без учёта регистра: This key is already in the list. Меню строки — Delete. Клик по строке ничего не делает.

Ключи по умолчанию: password, passwd, pwd, secret, token, authorization, cookie, apikey, sessionid, privatekey, creditcard, cardnumber, cvv, cvc, ssn, otp.

Сравнение ключей не учитывает регистр и разделители (api_key, api-key и apiKey — одно и то же). Фрагменты из 4 букв и короче должны совпадать с целым словом, поэтому pwd или otp не маскируют посторонние ключи.

Defaults напротив заголовка возвращает оба флажка и список ключей.

Значения чувствительных ключей заменяются на [MASKED]. Номера карт проверяются алгоритмом Луна.

Export ​

Compress report включён по умолчанию. Пока браузер умеет сжимать, подсказка пишет The HTML report is several times smaller. Needs Chrome / Edge 80+, Firefox 113+ or Safari 16.4+. Тогда JSON событий хранится в файле как gzip в base64. В браузере, который сжимать не умеет, флажок недоступен, а подсказка пишет Not supported in this browser. Needs Chrome / Edge 80+, Firefox 113+ or Safari 16.4+. Что лежит в файле, описано в Экспорте.
