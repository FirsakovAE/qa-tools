Экспорт ​

События вкладки Logs можно сохранить в HTML-отчёт и открыть в любом браузере. Это удобно для баг-репортов, передачи сценария коллегам и анализа вне страницы.

Общие сведения о вкладке: Работа с логами.

Формат экспорта ​

Любой экспорт — один HTML-файл: статический отчёт, который открывается в браузере. Отдельного экспорта в JSON нет.

Данные внутри отчёта компактные, как и в живом логе (см. Как хранятся события): изменения стора — диффы, запрос и ответ используют одну сетевую запись, одинаковые тела хранятся один раз, а одинаковые значения в любом событии хранятся один раз как общий снимок. Заголовки, состояния Before / After, значения снимков и данные запроса и ответа восстанавливаются при открытии отчёта.

Встроенные данные используют версию формата 1.

Что именно экспортируется ​

Export Logs ​

  • Без выбора — все события, видимые в таблице с учётом Search и фильтра Type.
  • С выбором — только строки, отмеченные в колонке чекбоксов; кнопка показывает Export Logs (n).
  • Сетевые события всегда экспортируются парой: если в фильтр или выбор попал только Send request или только Receive response запроса, второе событие тоже добавляется в файл. Кадр WebSocket остаётся тем событием, которое выбрано.

Кнопка неактивна, пока в отфильтрованном списке нет ни одного события.

Одно событие ​

Export event в меню ⋮ шапки детализации или в контекстном меню строки экспортирует одно событие.

Для сетевых событий пункт называется Export request & response: события Send request и Receive response одного запроса экспортируются вместе в одном файле, поэтому запрос и ответ никогда не разделяются. Событие WebSocket экспортируется само по себе.

Изменения Pinia при частичном экспорте ​

Событие Change store — дифф относительно предыдущего события того же стора. Если предыдущее событие не попало в экспорт (выбор строк, фильтр или одно событие), экспортируемое изменение дополнительно несёт полное состояние после него и старые значения изменённых полей, поэтому Before / After доступны и в файле.

Файлы ​

ЭкспортИмя файла
Export Logslogs_<дата>_<время>.html
Сетевая параlog_network_<дата>_<время>.html
Другое одиночное событиеlog_<тип>_<дата>_<время>.html

Данные маскируются в момент записи, поэтому в файлах те же замаскированные значения, что и в интерфейсе (см. Настройки логов).

HTML-отчёт ​

HTML-отчёт — один самодостаточный файл: стили, скрипты, иконка приложения и данные событий встроены внутрь. Отчёт в тёмной теме, не загружает внешние ресурсы и открывается с диска без интернета.

Боковая панель ​

  • Report — Overview и All events с общим количеством;
  • разделы по типам со счётчиками: Network (Send request, Receive response), WebSocket (WebSocket open, WebSocket sent, WebSocket received, WebSocket closed), Components (Change props, Emit), Pinia (Change store, Store action), Page (Navigation, JS error);
  • внизу — Download Vue Inspector со ссылкой на страницу проекта.
  • над ней — Support Vue Inspector: Monthly support открывает Boosty, Donate with USDT показывает адрес Tron (TRC-20), QR-код и кнопку Copy address.

Overview ​

Сводные карточки: Events, Errors, Failed requests, время первого и последнего события, длительность; счётчики по типам; сведения об экспорте.

Карточки Events, Errors и Failed requests кликабельны: они открывают All events с соответствующим фильтром. Активный фильтр показывается чипом над списком; клик по чипу снимает фильтр.

Список событий и детализация ​

  • Поиск в верхней панели; при включённом in data поиск идёт и по данным событий.
  • На All events есть выпадающий список Type с чекбоксами — тот же фильтр, что на вкладке Logs. По умолчанию включены все типы. Select all и Clear включают или выключают весь список. Если выключены все типы, список пуст. Фильтр действует на этой странице вместе с поиском и чипом Errors / Failed requests и не меняет разделы боковой панели.
  • Клик по строке открывает детализацию с теми же вкладками, что и в приложении (Overview, Params, Headers, Body, Changes, Before / After, State, Raw и т.д.).
  • Бинарный ответ показывает то же жёлтое уведомление, что и обрезанное тело, Binary response received. Body not included in report., над строкой типа (image/jpeg (986.2 KB) и Binary). Сама картинка в файл не встраивается.
  • WebSocket open, WebSocket sent, WebSocket received и WebSocket closed вынесены в отдельный раздел WebSocket. Сообщение, если это JSON, показывается с отступами. Над блоком стоит строка Sent или Received и размер, тем же шрифтом, что тип и вес бинарного файла. WebSocket closed разбирает историю на такие же отдельные сообщения. Overview показывает код закрытия, причину и No automatic reconnect, если это удалось определить.
  • Для сетевых событий Request или Response в шапке детализации переключает между запросом и его ответом. У кадра или открытия WebSocket кнопка Closed, у закрытия — Opened.
  • Locate открывает All events и прокручивает список так, чтобы это событие было в видимой области, так же как Request / Response показывает парное событие. Если его тип был выключен, тип включается, чтобы событие осталось в списке. Когда панель детализации закрывает список, Locate ещё и закрывает панель, чтобы событие было видно в списке.
  • Панель детализации закрывается стрелкой слева (тот же элемент, что в приложении) или клавишей Esc.
  • ↑ / ↓ — переход между событиями.
  • Выбранный раздел и событие сохраняются в адресе (#…): ссылкой на конкретное событие можно поделиться, и она переживает перезагрузку.
  • На узком экране список разделов открывается кнопкой меню. Его закрывают выбор раздела и нажатие за пределами панели. Строки событий показывают цветную полосу типа.
