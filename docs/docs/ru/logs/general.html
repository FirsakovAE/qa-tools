Работа с логами ​

Вкладка Logs — единый хронологический журнал того, что происходит на странице: сетевые запросы, изменения props и эмиты компонентов, изменения и экшены Pinia, навигация SPA и JS-ошибки. Она помогает восстановить сценарий по шагам и передать его в виде файла.

Вкладка видна всегда, располагается после Pinia Store и записывает события одинаково в расширении и в режиме Bookmark (Standalone).

Типы событий ​

ТипЧто записывается
Send requestИсходящий вызов fetch / XMLHttpRequest: URL, метод, инициатор, Params, Headers запроса, Authorization, Body запроса
Receive responseОтвет на этот вызов: статус, длительность, размер, Headers ответа, Body ответа, сетевая ошибка
WebSocket openСоединение открыто: URL и Headers рукопожатия. Свой тип в фильтре Type
WebSocket sentОдин исходящий кадр. Каждый кадр — отдельное событие
WebSocket receivedОдин входящий кадр. Каждый кадр — отдельное событие
WebSocket closedЗакрытие этого соединения: код, причина, длительность, размер и No automatic reconnect, если протокол говорит, что клиент сам новый сокет не откроет
Change propsИзменённые props компонента: список изменений и полные снимки Before / After
EmitСобытие компонента: компонент, имя события, аргументы, тип слушателя (regular / once), цепочка родителей
Change storeИзменённый state Pinia: список изменений и полные снимки Before / After. Сюда же относятся базовые состояния стора: Store initialized, Store snapshot и Store checkpoint (см. Как хранятся события)
Store actionВызов экшена Pinia: аргументы, результат или ошибка, статус, длительность
NavigationНавигация SPA: pushState, replaceState, popstate, hashchange с полями From / To. При старте записи и после Clear текущая страница записывается как snapshot
JS errorНеперехваченная ошибка, необработанный reject промиса или console.error страницы: сообщение, источник, место, компактный стек (см. JS errors)

Каждый сетевой вызов даёт два события, которые ссылаются на одну общую сетевую запись. Send request показывает то, что было отправлено, Receive response — то, что пришло в ответ. WebSocket пишет отдельное событие на открытие (WebSocket open), на каждый отправленный кадр, на каждый полученный кадр и на закрытие. Эти четыре типа есть в фильтре Type. Они ссылаются на одно сохранённое соединение, поэтому рукопожатие и текст кадров хранятся один раз. Если запрос изменён на Breakpoint, оба события показывают фактически отправленные и полученные данные.

Верхняя панель управления ​

Поиск ​

Поле поиска фильтрует таблицу. Активные критерии задаются в Options → Logs → Search Settings (см. Настройки логов):

РежимОписание
По имени событияЗаголовок, компонент, стор, URL
По ключуКлючи в данных события и пути изменений
По значениюЗначения в данных события

Для Change store и Change props поиск по ключу и значению идёт по изменённым путям и значениям; полные состояния ищутся в событиях Store initialized, Store snapshot и Store checkpoint.

Как и в других вкладках, запрос без кавычек ищет по подстроке, запрос в двойных кавычках "..." — точное совпадение. Минимальная длина запроса берётся из настроек поиска инспектора (по умолчанию 2 символа).

Type ​

Type оставляет в таблице только выбранные типы событий. По умолчанию включены все типы. Если выключить все, таблица будет пустой и покажет подсказку снова включить типы.

Индикаторы состояния ​

ЭлементНазначение
N или N/MСтрок после фильтров; при активном поиске или фильтре Type M — общее число событий в буфере
ignoredЧисло игнорируемых групп событий. По нажатию открывается Ignored events: можно снять одно правило или все сразу (Clear all)
PausedЗапись новых событий приостановлена

Управление журналом ​

ЭлементНазначение
Pause / ResumeОстановить и возобновить запись новых событий
ClearУдалить все записанные события
Export LogsЭкспорт событий в HTML-отчёт (см. Экспорт)

Рабочая область ​

Таблица событий ​

КолонкаСодержимое
ЧекбоксВыбор для экспорта
TimeВремя события с миллисекундами
TypeЦветной бейдж типа
EventЗаголовок и краткое описание (метод и путь, компонент и событие, стор и изменённые ключи и т.д.)

Строки подсвечиваются по уровню: ответы 4xx — предупреждение; 5xx, сетевые ошибки, упавшие экшены и JS-ошибки — ошибка.

Выбор для экспорта ​

Первая колонка содержит чекбоксы — на том же месте, где во вкладках Props и Pinia находится звезда избранного.

ДействиеРезультат
Клик по чекбоксуВыбрать / снять выбор строки
Shift + кликВыбрать диапазон от последней отмеченной строки
Ctrl / Cmd + клик по строкеПереключить выбор строки, не открывая детализацию
Чекбокс в шапкеВыбрать все / снять выбор

Когда строки выбраны, кнопка показывает Export Logs (n) и экспортирует только их. Без выбора экспортируются все отфильтрованные события.

Детализация события ​

Клик по строке открывает детализацию справа. Оформление повторяет Network: вкладки, таблицы «имя / значение» и блоки JSON в выбранном режиме JSON.

ТипВкладки
Send requestOverview, Params (n), Headers, Body, Raw
Receive responseOverview, Headers, Body, Raw
WebSocket openOverview, Headers, Messages (n), Raw
WebSocket sent, WebSocket receivedOverview, Headers, Message, Raw
WebSocket closedOverview, Headers, Messages (n), Raw
Change props, Change storeChanges (n), Before, After, Raw
Store initialized, Store snapshot, Store checkpointOverview, State, Raw
Store actionOverview, Arguments, Result / Error, Raw
EmitArguments (n), Overview, Raw
Navigation, JS errorOverview, Stack (для ошибок), Raw

Changes показывает разницу по путям: добавленные, удалённые и изменённые значения со старым и новым значением. Очень большие списки изменений обрезаются; полное состояние остаётся на вкладках Before / After.

Before / After изменения стора восстанавливаются из базового состояния стора и изменений после него. Если это невозможно (более ранних событий стора в журнале уже нет), вкладка сообщает об этом, а Changes по-прежнему показывает изменённые значения; значение, которое нельзя восстановить, отображается как not available.

Raw показывает событие со всеми восстановленными полями.

Если сетевое тело было больше заданного размера события, на вкладке Body показывается предупреждение с исходным размером.

Бинарный Receive response показывает ту же планку, что и Network, сразу под вкладками раздела: тип содержимого, размер и бейдж Binary, например image/jpeg (986.2 KB). Сам файл не сохраняется. Duration у Store action и Receive response выводится с двумя знаками после запятой (635.90 ms).

Действия с событием ​

Действия доступны в меню ⋮ в шапке детализации и в контекстном меню строки (правая кнопка мыши или ⋮ в строке):

ДействиеНазначение
Export eventЭкспорт одного события. Для сетевых событий пункт называется Export request & response: оба события запроса попадают в один файл. Событие WebSocket экспортирует только себя
Copy cURLСкопировать запрос как команду cURL (доступно и для Receive response: оба события используют общие данные запроса). У событий WebSocket этого действия нет
Open request event / Open response eventПерейти к парному сетевому событию. У WebSocket пункты называются Open connection event / Open close event
IgnoreПерестать записывать эту группу событий

Ignore работает по группам: один и тот же запрос (метод и путь), один и тот же компонент, один и тот же стор и т.д. События игнорируемых групп не записываются вовсе; вернуть запись можно в Options → Logs → Ignore list.

Принципы работы ​

Когда начинается запись ​

Запись начинается вместе с остальными модулями Vue Inspector в контексте вкладки. События хранятся на странице, поэтому история доступна, даже если открыть Logs позже, без перезагрузки страницы.

Как хранятся события ​

События хранят только исходные данные; заголовки, описания и полные состояния вычисляются при показе события.

  • Pinia. Если стор создаётся во время записи, событие Store initialized фиксирует его полное состояние. Если запись начинается на уже существующем сторе, событие Store snapshot фиксирует его текущее состояние. Дальше каждое событие Change store хранит только изменения. Before / After восстанавливаются из базового состояния и изменений до события. Переключение вкладок Inspector новых снимков не создаёт. Новый снимок записывается после Clear и после изменения настроек маскирования. Записанное состояние разделено так же, как на вкладке Pinia Store: в state — объявленный state, в getters — геттеры и данные, которые стор хранит вне объявленного state (например, поля, присвоенные в actions options-стора с пустым state()). Изменения обеих частей отслеживаются, поэтому пути изменений начинаются с state. или getters..
  • Network. Send request и Receive response ссылаются на одну общую сетевую запись. События WebSocket ссылаются на одно общее соединение: открытие, каждый кадр и закрытие. Одинаковые тела запросов и ответов (например, у опрашиваемого эндпоинта) хранятся один раз. Тик длительности, пока сокет молчит, нового события не добавляет.
  • Общие снимки. Одинаковые значения внутри любого события — пропсы, состояние стора, аргументы и результаты actions, аргументы emit, ошибки, навигация — хранятся один раз. Каждая следующая копия — ссылка на этот снимок. Вкладка Logs и HTML-отчёт восстанавливают полное значение, поэтому на экране те же данные, которые были записаны.

Лимиты ​

Стабильность длительных сессий обеспечивает общий бюджет памяти. При его достижении журнал отсекается по записи Navigation: удаляется каждое событие, зарегистрированное до этой навигации, независимо от типа — сетевые запросы и ответы, WebSocket, props, Pinia, emit, store actions и ошибки. События начиная с этой навигации сохраняются. Каждая более ранняя навигация — следующая точка отсечения, поэтому первым уходит самый старый период. Последняя навигация переписывается в снимок страницы на этот момент (from очищается), и события до неё удаляются так же. Если журнал всё ещё больше бюджета, оставшиеся события удаляются по возрасту, с самых старых. Самое новое событие сохраняется всегда, даже если одно превышает бюджет. По умолчанию события хранятся целиком; максимальный размер события можно включить. Группы событий можно отключить полностью. Значения по умолчанию и настройки описаны в разделе Настройки логов.

Send request и Receive response идут по лимиту Maximum HTTP requests (Options → Network, по умолчанию 500): более старый запрос уходит из лога вместе со своим ответом. WebSocket open, WebSocket sent, WebSocket received и WebSocket closed идут по лимиту Maximum WebSocket events (тот же экран, по умолчанию 500): каждая такая запись считается одной, самые старые удаляются. Оба кольца отдельно от бюджета памяти.

Цепочка Pinia отсечением не ломается. Изменения до точки отсечения собираются в один Store checkpoint с состоянием стора на этот момент; он ставится перед оставшимися событиями. Предыдущая база и diff, из которых она получилась, удаляются. Следующие Change store по-прежнему восстанавливают Before / After от этого checkpoint. Если следующее оставшееся событие стора уже содержит полное состояние, checkpoint не создаётся, а более старые события стора удаляются.

JS errors ​

События JS error приходят из трёх источников, они показаны в Overview как Source: Uncaught error, Unhandled rejection и console.error.

  • Только инспектируемая страница. Принадлежность ошибки странице определяется по её источнику (вызывающему коду в стеке), а не по тексту. Сообщения и ошибки самого Vue Inspector и других расширений браузера не записываются. Это касается и внутренних сообщений Vue Inspector о неудачных запросах fetch / XHR: такой запрос уже есть как событие Network. Собственный console.error приложения о неудачном запросе сохраняется.
  • console.error. Сообщение собирается так же, как в консоли браузера (%s, %d, %o и подобные подставляются, объекты показываются кратким превью); аргументы-объекты сохраняются в Raw. Location указывает на строку приложения, вызвавшую console.error, или на верхний кадр переданной ошибки. Больше 50 сообщений в секунду не записываются; следующее событие показывает, сколько пропущено (Suppressed).
  • Компактный стек. Сообщение сохраняется. Если кадров больше 10, остаются первые 5 и последние 5, а середина заменяется строкой … N more frames (stack truncated). Overview показывает Stack: Truncated с числом кадров, оставленных с каждого края.

Ошибки инспектируемой страницы остаются в консоли страницы и во вкладке Logs. В список ошибок расширения (chrome://extensions) они не попадают: там только сбои самого Vue Inspector. Сюда же относится исключение страницы из WebSocket send или close, например WebSocket is already in CLOSING or CLOSED state: обёртка, которая записывает кадр, выполняется в странице. Неудачный fetch, отменённый или прерванный по таймауту запрос и тело ответа, которое не удалось прочитать из‑за обрыва соединения (Failed to fetch, network error), записываются только строкой Network. Во время записи console.error страницы проходит через небольшой мост на стороне страницы, поэтому консоль браузера может указать этот мост как источник строки. Само сообщение и его стек не меняются.

Маскирование данных ​

Чувствительные данные маскируются в момент записи события, поэтому не попадают ни в интерфейс, ни в экспорт: пароли, токены, cookies, заголовки авторизации, номера карт и похожие ключи, а также JWT, учётные данные Bearer / Basic и номера карт внутри любого текста.
