История релизов ​

[2.0.0] - 2026-01-23 ​

Core ​

  • Добавлена поддержка корпоративной версии приложения, не требующей установки.
  • Добавлена система отслеживания версий и уведомлений о доступности новых обновлений.
  • Проект переведён в формат iframe и больше не использует popup как точку входа.

Производительность ​

  • Решена проблема мгновенной утечки памяти на статичных сайтах, включая Docusaurus и Hugo.

UI / UX ​

  • Проведён рефакторинг стилей и общего визуального оформления продукта.

[2.1.0] - 2026-02-02 ​

Core ​

  • Добавлена новая вкладка управления — Network.
  • Проведён редизайн приложения с учётом нового расположения в iframe вместо popup: на экране теперь доступно больше полезной информации.
  • Скорректирована вёрстка блоков JSON — блок отображается на всю высоту приложения.
  • Исправлено залипание вкладок при раннем открытии приложения: ранее для отображения вкладок Props и Pinia требовалась полная перезагрузка страницы.

Props ​

  • Исправлена ошибка, при которой избранные элементы Props не находились после обновления страницы или повторного прохождения сценариев.
  • Оптимизирована работа с Props для длительных сессий без избыточной нагрузки на CPU, проведён рефакторинг внутренней логики.
  • Переработана вкладка Props: улучшена работа с большим количеством объектов и поиск при наведении.
  • Из вкладки Props удалён режим Props only.

Network ​

  • Добавлен перехват всех вызовов fetch и XMLHttpRequest, за исключением запросов типа OPTIONS и запросов, инициированных расширением.
  • Добавлено отображение сводной информации по запросам: статус, метод, имя, время выполнения, размер.
  • Добавлен подробный просмотр запроса с разделами: параметры, авторизация, заголовки, запрос, ответ. Отображаются только заголовки, доступные в рамках CORS-ограничений браузера.
  • Добавлена возможность приостановки и возобновления записи запросов. Запись включена по умолчанию при первом открытии приложения.
  • Добавлен Breakpoint — остановка и модификация исходящего запроса перед отправкой.
  • Добавлен Mock Response — перехват заранее выбранного запроса с подменой ответа.
  • Добавлено быстрое копирование в буфер обмена URL-адресов, токенов и ключевых элементов.
  • Добавлена очистка всех записанных запросов одной кнопкой.
  • Реализована событийная архитектура без polling для минимального использования CPU.
  • Добавлено автоматическое определение двоичного содержимого — для таких данных отображаются только метаданные.

[2.5.0] - 2026-05-17 ​

Network ​

Добавлена возможность свернуть / развернуть разделы заголовком network Приложение теперь запоминает последнюю вкладку где работал пользователь, при открытии запроса, последующий будет открываться на той же вкладке. где пользователь работал с предыдущим запросом

Глобальная приостановка Breakpoint и Mock
На панели Network (справа, рядом с управлением записью журнала) добавлены две кнопки: приостановка / возобновление всех правил breakpoint (иконка с кругом и паузой, активное состояние — янтарный акцент) и приостановка / возобновление всех mock response (иконка shuffle, активное состояние — фиолетовый акцент). Правила не удаляются из Options → Network; при «выключении» перехват соответствующего типа на странице не выполняется. Те же флаги задаются чекбоксами Enable breakpoint rules и Enable mock responses в настройках списков; панель и Options синхронизированы. Индикаторы bp и mock в приглушённом стиле показывают, что глобально применение правил отключено.

Режим захвата сети: Advanced (расширенный)
В настройках Network доступен режим Advanced mode: расширение запрашивает дополнительные права и собирает полный набор заголовков запроса и ответа (в том числе те, что в обычной вкладке Network в DevTools не всегда видны ограничениями страницы). Режим Classic mode (ранее условно «сохранённый» снимок) по-прежнему показывает только заголовки в рамках стандартного, «классического» просмотра без обхода этих ограничений.

Важно для Standalone
Расширенный захват и связанные с ним возможности недоступны в Standalone: там по-прежнему используется только классический сценарий без расширенных заголовков и без меню/настроек Advanced.

Что даёт Advanced mode в Network

  • Дополнительные заголовки в блоках Request / Response на вкладке заголовков выбранного запроса.
  • Закрепление заголовков (pin) — выбранные имена можно закрепить вверху списка отдельно для запроса и ответа; список закреплений можно править в настройках (только при включённом Advanced).
  • Свои ссылки по заголовку (header links) — для хоста и шаблона URL можно открывать внешний ресурс с подстановкой значения заголовка (например, переход к трейсам, поиску по ID, внутренним дашбордам). Управление правилами — в настройках Network и через контекстное меню строки заголовка (при Advanced).
  • Настройки Header links и Pinned headers в опциях отображаются только при включённом Advanced mode, чтобы не перегружать интерфейс в классическом режиме.

UI / UX ​

JSON Mode (Options → General)
В разделе Options → General добавлен переключатель JSON Mode с двумя вариантами:

  • Classic — встроенный текстовый редактор с подсветкой синтаксиса (Prism, JsonTextEditor): один текстовый вид без дерева, оптимизирован для больших фрагментов (ослабление подсветки на очень длинных JSON и облегчённый просмотр для крупных не-JSON тел только для чтения).
  • Advanced — редактор на базе vanilla-jsoneditor: два представления одного JSON — Text (код) и Tree (структура); переключение с панели инструментов, последний выбранный режим (Text / Tree) сохраняется в настройках (json.mode). В Advanced доступны Format / Compact (где разрешено редактирование), Undo / Redo, поиск, копирование; в дереве — свёртка/развёртка узлов, навигация по пути, контекстные меню и связанные с деревом сценарии сортировки и правки.

Переключатель Classic / Advanced задаёт реализацию для JSON в интерфейсе (тела запросов/ответов в Network, Mock, снимки Pinia, JSON на Props и т.д.). Для контента не в формате JSON по-прежнему используется текстовый просмотр с подсветкой, где это поддерживается.

[2.6.0] - 2026-10-17 ​

Logs ​

Новая вкладка Logs — единый хронологический журнал событий страницы. Доступна в расширении и режиме Bookmark (Standalone), всегда располагается после Pinia Store.

Типы событий ​

  • Send request / Receive response — запросы и ответы fetch / XMLHttpRequest с параметрами, заголовками, телом, статусом, длительностью и размером.
  • WebSocket open / WebSocket sent / WebSocket received / WebSocket closed — открытие и закрытие соединений, отправленные и полученные сообщения, заголовки, длительность и причина закрытия.
  • Change props — изменения props компонентов со сравнением Before / After.
  • Emit — события компонентов, аргументы, тип слушателя и цепочка родителей.
  • Change store — изменения состояния Pinia со сравнением Before / After. Для существующих сторов сохраняется начальный снимок, для новых — полное состояние при создании.
  • Store action — аргументы, результат или ошибка, статус и длительность экшенов Pinia.
  • Navigation — навигация SPA с полями From / To. При запуске записи и после Clear сохраняется текущая страница.
  • JS error — неперехваченные ошибки, необработанные отклонения промисов и вызовы console.error страницы. Отображаются сообщение, источник, место возникновения и стек вызовов. Сообщения самого Vue Inspector и других расширений браузера не записываются.

Таблица и детализация ​

  • Колонки Time, Type, Event с подсветкой ошибок и неудачных запросов: 4xx — предупреждение, 5xx и ошибки — критический статус.
  • Фильтрация по типу события и поиск по названиям, ключам и значениям. Режимы поиска настраиваются в Options → Logs → Search Settings; запрос в кавычках ищет точное совпадение.
  • Pause приостанавливает запись, Clear очищает журнал. События собираются с момента запуска инспектора, даже если вкладка Logs открыта позже.
  • Детализация зависит от типа события и содержит необходимые сведения, включая параметры запросов, заголовки, JSON, сообщения WebSocket, аргументы событий и снимки состояния.
  • Для изменений props и Pinia доступен diff добавленных, удалённых и изменённых путей.
  • Меню действий: Export event, Copy cURL, переход к парному запросу или ответу, Ignore для прекращения записи выбранной группы событий.

Выбор и экспорт ​

  • Выбор событий чекбоксами, Shift + клик для диапазона, Ctrl / Cmd + клик для переключения отдельных строк.
  • Export Logs (n) экспортирует выбранные события. Если ничего не выбрано — все события с учётом текущих фильтров.
  • Запросы и ответы всегда экспортируются вместе.
  • Export Logs и экспорт отдельного события создают автономный HTML-отчёт версии 1, который открывается без интернета.
  • Для изменений Pinia в отчёте сохраняются данные, необходимые для просмотра Before / After, даже если предыдущие события не экспортированы.

HTML report ​

Автономный HTML-отчёт с тёмной темой, без внешних ресурсов.

  • Разделы Report, Network, WebSocket, Components, Pinia, Page со счётчиками событий.
  • Сводка Overview, карточки Events, Errors и Failed requests с переходом к соответствующим событиям.
  • Поиск по заголовкам и содержимому данных (in data).
  • Навигация с клавиатуры (↑ / ↓, Esc) и прямые ссылки на события.
  • Детализация с теми же вкладками, что и в Logs, переход между запросом и ответом.
  • Locate открывает список событий и показывает выбранное событие в видимой области.
  • Раздел Support Vue Inspector со ссылками на Boosty и возможностью пожертвования в USDT через Tron (TRC-20).

Network ​

  • Выбор запросов чекбоксами и экспорт только выбранных записей через Export Collection (n).
  • Счётчики bp и mock открывают список активных правил. Pause приостанавливает правило, × удаляет его.
  • На узкой панели сохранение Breakpoint / Mock или выход из формы кнопкой назад закрывает детали запроса. На широкой панели они остаются открытыми.
  • После изменения запроса или ответа через Breakpoint отображаются фактически отправленные данные.
  • WebSocket-соединения отображаются отдельными строками WS, включая открытые до запуска инспектора.
  • Headers показывает заголовки рукопожатия, Messages — отправленные и полученные кадры, новые сверху. JSON форматируется; отображаются направление и размер сообщения.
  • Хранятся последние 200 сообщений соединения. WebSocket не включается в Export Collection; Breakpoint и Mock остаются доступны для HTTP.
  • В Logs и HTML-отчёте события WebSocket записываются отдельно: open, sent, received, closed.
  • Для распознанных закрытий Centrifuge, например 3501, отображаются причина и No automatic reconnect. При отправке {} в таком соединении показывается предупреждение о возможном закрытии.
  • Для бинарных ответов отображается уведомление с типом содержимого; в HTML-отчёте оно оформлено так же, как предупреждение об обрезанных данных.

Props / Pinia Store ​

Исправлено сохранение удалённых ключей в режиме Edit.

  • Pinia — вложенные ключи удаляются из стора; удаление ключей верхнего уровня корректно обрабатывается для options-store и setup-store.
  • Props — при удалении prop применяется значение по умолчанию Vue: default, false для Boolean, иначе undefined. Вложенные ключи объектных props удаляются.

Options → Logs ​

  • Search Settings — режимы поиска по умолчанию.
  • Ignore list — управление игнорируемыми группами событий: Log again, Log all again.
  • Logs and limits — включение и отключение типов событий, бюджет памяти, ограничение размера события и индикатор Used X of Y.
  • Data masking — настройка маскирования чувствительных данных, шаблонов и списка ключей.

Хранение данных и ограничения ​

  • Чувствительные данные маскируются при записи по ключам и шаблонам значений, включая JWT, Bearer / Basic и номера карт.
  • Бюджет памяти по умолчанию — 20 МБ. При достижении лимита удаляются старые события.
  • История изменений Pinia сжимается в Store checkpoint, сохраняя возможность просмотра оставшихся изменений.
  • Повторяющиеся значения хранятся один раз, а в интерфейсе и HTML-отчёте восстанавливаются полностью.
  • По умолчанию события сохраняются целиком. Необязательный лимит размера события — 512 КБ — позволяет ограничить объём данных, отбрасывая крупные части событий и обрезая сетевые тела.
