# История релизов

## [2.0.0] - 2026-01-23

### Core

* Добавлена поддержка корпоративной версии приложения, не требующей установки.
* Добавлена система отслеживания версий и уведомлений о доступности новых обновлений.
* Проект переведён в формат **iframe** и больше не использует **popup** как точку входа.

---

### Производительность

* Решена проблема мгновенной утечки памяти на статичных сайтах, включая **Docusaurus** и **Hugo**.

---

### UI / UX

* Проведён рефакторинг стилей и общего визуального оформления продукта.

## [2.1.0] - 2026-02-02

### Core

* Добавлена новая вкладка управления — **Network**.
* Проведён редизайн приложения с учётом нового расположения в **iframe** вместо **popup**: на экране теперь доступно больше полезной информации.
* Скорректирована вёрстка блоков **JSON** — блок отображается на всю высоту приложения.
* Исправлено залипание вкладок при раннем открытии приложения: ранее для отображения вкладок **Props** и **Pinia** требовалась полная перезагрузка страницы.

---

### Props

* Исправлена ошибка, при которой избранные элементы **Props** не находились после обновления страницы или повторного прохождения сценариев.
* Оптимизирована работа с **Props** для длительных сессий без избыточной нагрузки на CPU, проведён рефакторинг внутренней логики.
* Переработана вкладка **Props**: улучшена работа с большим количеством объектов и поиск при наведении.
* Из вкладки **Props** удалён режим **Props only**.

---

### Network

* Добавлен перехват всех вызовов **fetch** и **XMLHttpRequest**, за исключением запросов типа **OPTIONS** и запросов, инициированных расширением.
* Добавлено отображение сводной информации по запросам: статус, метод, имя, время выполнения, размер.
* Добавлен подробный просмотр запроса с разделами: параметры, авторизация, заголовки, запрос, ответ. Отображаются только заголовки, доступные в рамках **CORS**-ограничений браузера.
* Добавлена возможность приостановки и возобновления записи запросов. Запись включена по умолчанию при первом открытии приложения.
* Добавлен **Breakpoint** — остановка и модификация исходящего запроса перед отправкой.
* Добавлен **Mock Response** — перехват заранее выбранного запроса с подменой ответа.
* Добавлено быстрое копирование в буфер обмена URL-адресов, токенов и ключевых элементов.
* Добавлена очистка всех записанных запросов одной кнопкой.
* Реализована событийная архитектура без **polling** для минимального использования CPU.
* Добавлено автоматическое определение двоичного содержимого — для таких данных отображаются только метаданные.

## [2.5.0] - 2026-05-17

### Network

Добавлена возможность свернуть / развернуть разделы заголовком network
Приложение теперь запоминает последнюю вкладку где работал пользователь, при открытии запроса, последующий будет открываться на той же вкладке. где пользователь работал с предыдущим запросом

**Глобальная приостановка Breakpoint и Mock**  
На панели **Network** (справа, рядом с управлением записью журнала) добавлены две кнопки: **приостановка / возобновление всех правил breakpoint** (иконка с кругом и паузой, активное состояние — янтарный акцент) и **приостановка / возобновление всех mock response** (иконка shuffle, активное состояние — фиолетовый акцент). Правила не удаляются из **Options → Network**; при «выключении» перехват соответствующего типа на странице не выполняется. Те же флаги задаются чекбоксами **Enable breakpoint rules** и **Enable mock responses** в настройках списков; панель и Options синхронизированы. Индикаторы **bp** и **mock** в приглушённом стиле показывают, что глобально применение правил отключено.

**Режим захвата сети: Advanced (расширенный)**  
В настройках Network доступен режим **Advanced mode**: расширение запрашивает дополнительные права и собирает **полный набор заголовков** запроса и ответа (в том числе те, что в обычной вкладке Network в DevTools не всегда видны ограничениями страницы). Режим **Classic mode** (ранее условно «сохранённый» снимок) по-прежнему показывает только заголовки в рамках стандартного, «классического» просмотра без обхода этих ограничений.

**Важно для Standalone**  
Расширенный захват и связанные с ним возможности **недоступны в Standalone**: там по-прежнему используется только классический сценарий без расширенных заголовков и без меню/настроек Advanced.

**Что даёт Advanced mode в Network**

- **Дополнительные заголовки** в блоках Request / Response на вкладке заголовков выбранного запроса.
- **Закрепление заголовков (pin)** — выбранные имена можно закрепить вверху списка отдельно для **запроса** и **ответа**; список закреплений можно править в настройках (только при включённом Advanced).
- **Свои ссылки по заголовку (header links)** — для хоста и шаблона URL можно открывать внешний ресурс с подстановкой значения заголовка (например, переход к **трейсам**, поиску по ID, внутренним дашбордам). Управление правилами — в настройках Network и через контекстное меню строки заголовка (при Advanced).
- Настройки **Header links** и **Pinned headers** в опциях отображаются **только при включённом Advanced mode**, чтобы не перегружать интерфейс в классическом режиме.

### UI / UX

**JSON Mode (Options → General)**  
В разделе **Options → General** добавлен переключатель **JSON Mode** с двумя вариантами:

- **Classic** — встроенный текстовый редактор с подсветкой синтаксиса (**Prism**, **JsonTextEditor**): один текстовый вид без дерева, оптимизирован для больших фрагментов (ослабление подсветки на очень длинных JSON и облегчённый просмотр для крупных не-JSON тел только для чтения).
- **Advanced** — редактор на базе **vanilla-jsoneditor**: два представления одного JSON — **Text** (код) и **Tree** (структура); переключение с панели инструментов, последний выбранный режим (**Text** / **Tree**) **сохраняется** в настройках (**json.mode**). В Advanced доступны **Format** / **Compact** (где разрешено редактирование), **Undo / Redo**, **поиск**, копирование; в дереве — свёртка/развёртка узлов, навигация по пути, контекстные меню и связанные с деревом сценарии сортировки и правки.

Переключатель **Classic / Advanced** задаёт реализацию для **JSON** в интерфейсе (тела запросов/ответов в **Network**, **Mock**, снимки **Pinia**, JSON на **Props** и т.д.). Для контента не в формате JSON по-прежнему используется текстовый просмотр с подсветкой, где это поддерживается.


## [2.6.0] - 2026-10-12

### Logs

Новая вкладка **Logs** — единый хронологический журнал того, что происходит на странице. Вкладка видна всегда, располагается после **Pinia Store** и работает как в расширении, так и в режиме **Bookmark** (Standalone).

#### Типы событий

* **Send request** / **Receive response** — каждый вызов **fetch** / **XMLHttpRequest** записывается двумя событиями с одной общей сетевой записью. Событие запроса показывает **Params**, **Headers**, **Authorization** и **Body** запроса, событие ответа — **Status**, **Duration**, **Size**, **Headers** и **Body** ответа.
* **Change props** — изменённые props компонента со списком изменений и полными снимками **Before** / **After**.
* **Emit** — события компонентов: компонент, имя события, аргументы, тип слушателя (**regular** / **once**), цепочка родителей.
* **Change store** — изменённый state **Pinia** со списком изменений и полными снимками **Before** / **After**. Стор, созданный во время записи, получает событие **Store initialized** с полным состоянием, уже существовавший к началу записи — **Store snapshot**; следующие события хранят только изменения, а **Before** / **After** восстанавливаются по ним. Записанное состояние стора разделено так же, как на вкладке **Pinia Store**: в `state` — объявленный state, в `getters` — геттеры и данные, которые стор хранит вне объявленного state (например, поля, присвоенные в actions options-стора с пустым `state()`); изменения обеих частей записываются.
* **Store action** — вызовы экшенов **Pinia**: аргументы, результат или ошибка, статус и длительность.
* **Navigation** — навигация SPA (**pushState**, **replaceState**, **popstate**, **hashchange**) с полями **From** / **To**.
* **JS error** — неперехваченные ошибки, необработанные reject промисов и вызовы `console.error` страницы: сообщение, источник, место и компактный стек (10 верхних кадров, усечение помечается). Сообщения самого Vue Inspector и других расширений браузера не записываются, в том числе его внутренние сообщения о неудачных запросах fetch / XHR (они уже есть как события **Network**); собственные сообщения приложения об ошибках запросов сохраняются. Ошибки инспектируемой страницы не попадают в список ошибок расширения (`chrome://extensions`); там остаются только сбои самого Vue Inspector.

#### Таблица логов

* Колонки: **Time**, **Type**, **Event**; упавшие запросы и ошибки подсвечиваются (**4xx** — предупреждение, **5xx** / сетевые ошибки / упавшие экшены / JS-ошибки — ошибка).
* Фильтр **Type**: по умолчанию включены все типы; если выключить все, ничего не отображается.
* Поиск по имени события (заголовок, компонент, стор, URL), по ключу (ключи данных и пути изменений) и по значению; режимы задаются в **Options → Logs → Search Settings**. Запрос в кавычках ищет точное совпадение.
* **Pause** / возобновление записи и **Clear**.
* События записываются на странице с момента загрузки инспектора, поэтому история доступна, даже если открыть вкладку позже.

#### Детализация события

* Детализация оформлена так же, как в **Network**: вкладки, таблицы «имя / значение» и блоки **JSON** в выбранном режиме JSON.
* Набор вкладок зависит от типа:

  * **Send request** — **Overview**, **Params (n)**, **Headers**, **Body**, **Raw**;
  * **Receive response** — **Overview**, **Headers**, **Body**, **Raw**;
  * **Change props** / **Change store** — **Changes (n)** (diff с добавленными / удалёнными / изменёнными путями), **Before**, **After**, **Raw**;
  * **Store initialized** / **Store snapshot** / **Store checkpoint** — **State**, **Overview**, **Raw**;
  * **Store action** — **Overview**, **Arguments**, **Result** / **Error**, **Raw**;
  * **Emit** — **Arguments (n)**, **Overview**, **Raw**;
  * **Navigation** / **JS error** — **Overview**, **Stack** (для ошибок), **Raw**.

* Действия собраны в меню **⋮** шапки детализации и в контекстном меню строки:

  * **Export event** — экспорт одного события; для **Send request** / **Receive response** это **Export request & response**, оба события запроса попадают в один файл;
  * **Copy cURL** — для обоих сетевых событий (у них общие данные запроса);
  * **Open request event** / **Open response event** — переход к парному сетевому событию;
  * **Ignore** — перестать записывать эту группу событий (тот же запрос, компонент, стор и т.д.).

#### Выбор для экспорта

* В начало таблицы **Logs** добавлена колонка с чекбоксами (на месте звезды избранного во вкладках **Props** и **Pinia**).
* Горячие клавиши: **Shift + клик** — выбор диапазона, **Ctrl / Cmd + клик** по строке — переключение строки, **Ctrl / Cmd + A** — выбор всех отфильтрованных строк; чекбокс в шапке выбирает или снимает всё.
* При выбранных строках **Export Logs (n)** экспортирует только их; без выбора экспортируются все отфильтрованные события. Сетевые события всегда экспортируются парой (запрос + ответ).

#### Экспорт

* **Export Logs** и экспорт одного события скачивают **HTML**-отчёт (версия формата 1), который открывается без интернета. Событие **Change store**, предыдущее событие стора которого не попало в экспорт, несёт полное состояние, поэтому **Before** / **After** доступны и в файле.
* Отчёт — статический и самодостаточный (тёмная тема, без внешних ресурсов), повторяющий вкладку **Logs**:

  * навигация по разделам в боковой панели (**Report**, **Network**, **Components**, **Pinia**, **Page**) со счётчиками событий;
  * **Overview** со сводными карточками; **Events**, **Errors** и **Failed requests** открывают **All events** с соответствующим фильтром;
  * поиск по заголовкам или внутри данных (**in data**), навигация с клавиатуры (**↑ / ↓**, **Esc**), прямые ссылки на выбранное событие;
  * детализация с теми же вкладками, что и в приложении, кнопкой перехода между запросом и ответом и **All events →**, которая открывает **All events** и ставит это событие в начало списка;
  * **Support Vue Inspector** над **Download Vue Inspector**: **Monthly support** открывает Boosty, **Donate with USDT** показывает адрес Tron (TRC-20), QR-код и **Copy address**.

#### Безопасность данных и лимиты

* Чувствительные данные маскируются в момент записи события и не попадают ни в интерфейс, ни в экспорт:

  * по ключу: password, token, secret, authorization, cookie, apikey, номер карты, cvv, otp и другие (список редактируется);
  * по значению: **JWT**, учётные данные **Bearer** / **Basic** и номера карт внутри любого текста.

* Каждую группу событий (**Network**, **Props changes**, **Emits**, **Pinia changes**, **Store actions**, **Navigation**, **JS errors**) можно отключить чекбоксом: она не логируется совсем.
* Старые события **Change store** не удаляются, а сжимаются в **Store checkpoint** (*начальное состояние → checkpoint → последние изменения*), поэтому у оставшихся изменений сохраняются **Before** / **After**.
* Общий **бюджет памяти** (по умолчанию 20 МБ): при его достижении удаляются самые старые события, самое новое сохраняется всегда. Сетевая запись, общая для запроса и ответа, и одинаковые тела учитываются один раз. Уже сохранённый в настройках бюджет остаётся до нажатия **Defaults**.
* Одинаковые значения внутри любого события хранятся один раз, повторные копии становятся ссылками. Вкладка **Logs** и HTML-отчёт восстанавливают полное значение, а **Export Logs** больше не разворачивает эти копии в основном потоке.
* По умолчанию события хранятся целиком (состояния стора, props, аргументы emit, сетевые тела), поэтому экспортированный отчёт содержит полные данные. Необязательный **максимальный размер события** (по умолчанию 512 КБ) отбрасывает крупные части события и обрезает сетевые тела с пометкой в детализации.

#### Options → Logs

* **Search Settings** — режимы поиска по умолчанию.
* **Ignore list** — игнорируемые группы событий с действиями **Log again** и **Log all again**.
* **Logs and limits** — чекбоксы групп событий, бюджет памяти, необязательный максимальный размер события (поле размера видно только при включённом **Limit event size**), текущее использование (**Used X of Y**) и **Defaults**.
* **Data masking** — включение маскирования, поиск шаблонов в значениях, свой список ключей и **Default keys**. В описании сказано, что значения маскируются в момент записи события.

* В начало таблицы **Network** добавлена колонка с чекбоксами и теми же горячими клавишами, что в **Logs**; **Export Collection (n)** экспортирует только выбранные запросы. Чекбокс в заголовке окрашен в цвет текста заголовка; чекбоксы в строках без изменений (то же во вкладке **Logs**).

* На узкой панели сохранение breakpoint или mock, а также выход из этой формы кнопкой назад, закрывает окно деталей запроса. На широкой панели детали остаются открытыми.
* После изменения запроса на **Breakpoint** вкладки **Network** и **Logs** показывают фактически отправленные данные (URL, метод, заголовки, тело), а не данные до остановки.

### Props / Pinia Store

* Удаление ключей в режиме **Edit** теперь сохраняется:

  * **Pinia** — удалённые вложенные ключи удаляются из стора; удалённые ключи верхнего уровня удаляются (options-store) или получают `undefined` с сохранением связи ref (setup-store);
  * **Props** — удалённый prop получает значение, которое Vue использует для непереданного prop: **default**, `false` для **Boolean**, иначе `undefined`; удалённые ключи внутри объектного prop удаляются.
