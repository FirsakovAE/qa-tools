# Экспорт и импорт

События вкладки **Logs** можно сохранить в **HTML**-отчёт и открыть снова — в любом браузере или через **Import Logs** в Vue Inspector. Это удобно для баг-репортов, передачи сценария коллегам и анализа вне страницы.

Общие сведения о вкладке: [Работа с логами](./general.md).

---

## Формат экспорта

Любой экспорт — один **HTML**-файл: статический отчёт для просмотра и структурированные данные событий, которые читает **Import Logs**. Отдельного экспорта в JSON нет.

Данные внутри отчёта компактные, как и в живом логе (см. [Как хранятся события](./general.md#how-events-are-stored)): изменения стора — диффы, запрос и ответ используют одну сетевую запись, одинаковые тела хранятся один раз, а одинаковые значения в любом событии хранятся один раз как общий снимок. Заголовки, состояния Before / After, значения снимков и данные запроса и ответа восстанавливаются при открытии отчёта.

У встроенных данных есть версия формата. Файлы из более новых версий Vue Inspector отклоняются с сообщением, а не читаются неверно.

## Что именно экспортируется

### Export Logs

* Без выбора — все события, видимые в таблице с учётом **Search** и фильтра **Type**.
* С выбором — только строки, отмеченные в колонке чекбоксов; кнопка показывает **Export Logs (n)**.
* Сетевые события всегда экспортируются парой: если в фильтр или выбор попал только **Send request** или только **Receive response** запроса, второе событие тоже добавляется в файл.

Кнопка неактивна, пока в отфильтрованном списке нет ни одного события.

### Одно событие

**Export event** в меню **⋮** шапки детализации или в контекстном меню строки экспортирует одно событие.

Для сетевых событий пункт называется **Export request & response**: события **Send request** и **Receive response** одного запроса экспортируются вместе в одном файле, поэтому запрос и ответ никогда не разделяются.

### Изменения Pinia при частичном экспорте

Событие **Change store** — дифф относительно предыдущего события того же стора. Если предыдущее событие не попало в экспорт (выбор строк, фильтр или одно событие), экспортируемое изменение дополнительно несёт полное состояние после него и старые значения изменённых полей, поэтому **Before** / **After** доступны и в файле.

### Файлы

| Экспорт | Имя файла |
| ------- | --------- |
| **Export Logs** | `logs_<дата>_<время>.html` |
| Сетевая пара | `log_network_<дата>_<время>.html` |
| Другое одиночное событие | `log_<тип>_<дата>_<время>.html` |

Данные маскируются в момент записи, поэтому в файлах те же замаскированные значения, что и в интерфейсе (см. [Настройки логов](./settings.md#data-masking)).

## HTML-отчёт

**HTML**-отчёт — один самодостаточный файл: стили, скрипты, иконка приложения и данные событий встроены внутрь. Отчёт в тёмной теме, не загружает внешние ресурсы и открывается с диска без интернета.

### Боковая панель

* **Report** — **Overview** и **All events** с общим количеством;
* разделы по типам со счётчиками: **Network** (**Send request**, **Receive response**), **Components** (**Change props**, **Emit**), **Pinia** (**Change store**, **Store action**), **Page** (**Navigation**, **JS error**);
* внизу — **Download Vue Inspector** со ссылкой на страницу проекта.

### Overview

Сводные карточки: **Events**, **Errors**, **Failed requests**, время первого и последнего события, длительность; счётчики по типам; сведения об экспорте.

Карточки **Events**, **Errors** и **Failed requests** кликабельны: они открывают **All events** с соответствующим фильтром. Активный фильтр показывается чипом над списком; клик по чипу снимает фильтр.

### Список событий и детализация

* Поиск в верхней панели; при включённом **in data** поиск идёт и по данным событий.
* На **All events** есть выпадающий список **Type** с чекбоксами — тот же фильтр, что на вкладке **Logs**. По умолчанию включены все типы. **Select all** и **Clear** включают или выключают весь список. Если выключены все типы, список пуст. Фильтр действует на этой странице вместе с поиском и чипом **Errors** / **Failed requests** и не меняет разделы боковой панели.
* Клик по строке открывает детализацию с теми же вкладками, что и в приложении (**Overview**, **Params**, **Headers**, **Body**, **Changes**, **Before** / **After**, **State**, **Raw** и т.д.).
* Для сетевых событий кнопка рядом с **Close** переключает между запросом и его ответом.
* **↑ / ↓** — переход между событиями, **Esc** — закрыть детализацию.
* Выбранный раздел и событие сохраняются в адресе (`#…`): ссылкой на конкретное событие можно поделиться, и она переживает перезагрузку.

## Импорт

**Import Logs** открывает **HTML**-отчёт, экспортированный из вкладки **Logs**. Файлы **JSON** и **HTML** из предыдущих версий тоже открываются.

* Импортированные события показываются в отдельном режиме только для чтения. В баннере — имя файла, число событий и время экспорта.
* **Back to live logs** возвращает к живой записи; живые события не теряются, пока открыт файл.
* Некорректные события пропускаются (их число показывается в сообщении об импорте).
* HTML-файлы, которые не являются отчётом Logs, отклоняются с сообщением.
* Импортированные данные повторно проходят через текущие настройки маскирования.

В файлах предыдущих версий половины запроса и ответа сетевой записи снова объединяются в одну запись.
