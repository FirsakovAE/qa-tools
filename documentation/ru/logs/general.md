# Работа с логами

Вкладка **Logs** — единый хронологический журнал того, что происходит на странице: сетевые запросы, изменения props и эмиты компонентов, изменения и экшены **Pinia**, навигация SPA и JS-ошибки. Она помогает восстановить сценарий по шагам и передать его в виде файла.

Вкладка видна всегда, располагается после **Pinia Store** и одинаково работает в расширении и в режиме **Bookmark** ([Standalone](/ru/standalone)).

## Типы событий

| Тип | Что записывается |
| --- | ---------------- |
| **Send request** | Исходящий вызов **fetch** / **XMLHttpRequest**: URL, метод, инициатор, **Params**, **Headers** запроса, **Authorization**, **Body** запроса |
| **Receive response** | Ответ на этот вызов: статус, длительность, размер, **Headers** ответа, **Body** ответа, сетевая ошибка |
| **Change props** | Изменённые props компонента: список изменений и полные снимки **Before** / **After** |
| **Emit** | Событие компонента: компонент, имя события, аргументы, тип слушателя (**regular** / **once**), цепочка родителей |
| **Change store** | Изменённый state **Pinia**: список изменений и полные снимки **Before** / **After** |
| **Store action** | Вызов экшена **Pinia**: аргументы, результат или ошибка, статус, длительность |
| **Navigation** | Навигация SPA: **pushState**, **replaceState**, **popstate**, **hashchange** с полями **From** / **To** |
| **JS error** | Неперехваченная ошибка или необработанный reject промиса: сообщение, место, стек |

Каждый сетевой вызов даёт **два** события. **Send request** хранит только то, что было отправлено, **Receive response** — только то, что пришло в ответ; оба сохраняют URL и метод, чтобы пару можно было найти. Если запрос изменён на [Breakpoint](/ru/network/traffic), оба события содержат фактически отправленные и полученные данные.

## Верхняя панель управления

### Поиск

Поле поиска фильтрует таблицу. Активные критерии задаются в **Options → Logs → Search Settings** (см. [Настройки логов](./settings.md)):

| Режим | Описание |
| ----- | -------- |
| **По имени события** | Заголовок, компонент, стор, URL |
| **По ключу** | Ключи в данных события и пути изменений |
| **По значению** | Значения в данных события |

Как и в других вкладках, запрос **без** кавычек ищет по подстроке, запрос в **двойных кавычках** `"..."` — точное совпадение. Минимальная длина запроса берётся из настроек поиска инспектора (по умолчанию **2** символа).

### Type

**Type** оставляет в таблице только выбранные типы событий. По умолчанию включены все типы. Если выключить все, таблица будет пустой и покажет подсказку снова включить типы.

### Индикаторы состояния

| Элемент | Назначение |
| ------- | ---------- |
| **N** или **N/M** | Строк после фильтров; при активном поиске или фильтре **Type** **M** — общее число событий в буфере |
| **ignored** | Число игнорируемых групп событий. По нажатию открывается **Ignored events**: можно снять одно правило или все сразу (**Clear all**) |
| **Paused** | Запись новых событий приостановлена |

### Управление журналом

| Элемент | Назначение |
| ------- | ---------- |
| **Pause** / **Resume** | Остановить и возобновить запись новых событий |
| **Clear** | Удалить все записанные события |
| **Export Logs** | Экспорт событий в файл (см. [Экспорт и импорт](./export.md)) |
| **Import Logs** | Открыть экспортированный файл **JSON** или **HTML** |

## Рабочая область

### Таблица событий

| Колонка | Содержимое |
| ------- | ---------- |
| Чекбокс | Выбор для экспорта |
| **Time** | Время события с миллисекундами |
| **Type** | Цветной бейдж типа |
| **Event** | Заголовок и краткое описание (метод и путь, компонент и событие, стор и изменённые ключи и т.д.) |

Строки подсвечиваются по уровню: ответы **4xx** — предупреждение; **5xx**, сетевые ошибки, упавшие экшены и JS-ошибки — ошибка.

### Выбор для экспорта

Первая колонка содержит чекбоксы — на том же месте, где во вкладках **Props** и **Pinia** находится звезда избранного.

| Действие | Результат |
| -------- | --------- |
| Клик по чекбоксу | Выбрать / снять выбор строки |
| **Shift** + клик | Выбрать диапазон от последней отмеченной строки |
| **Ctrl / Cmd** + клик по строке | Переключить выбор строки, не открывая детализацию |
| **Ctrl / Cmd** + **A** (фокус на таблице) | Выбрать все отфильтрованные строки |
| Чекбокс в шапке | Выбрать все / снять выбор |

Когда строки выбраны, кнопка показывает **Export Logs (n)** и экспортирует только их. Без выбора экспортируются все отфильтрованные события.

### Детализация события

Клик по строке открывает детализацию справа. Оформление повторяет **Network**: вкладки, таблицы «имя / значение» и блоки **JSON** в выбранном [режиме JSON](/ru/options/json_mode).

| Тип | Вкладки |
| --- | ------- |
| **Send request** | **Overview**, **Params (n)**, **Headers**, **Body**, **Raw** |
| **Receive response** | **Overview**, **Headers**, **Body**, **Raw** |
| **Change props**, **Change store** | **Changes (n)**, **Before**, **After**, **Raw** |
| **Store action** | **Overview**, **Arguments**, **Result** / **Error**, **Raw** |
| **Emit** | **Arguments (n)**, **Overview**, **Raw** |
| **Navigation**, **JS error** | **Overview**, **Stack** (для ошибок), **Raw** |

**Changes** показывает разницу по путям: добавленные, удалённые и изменённые значения со старым и новым значением. Очень большие списки изменений обрезаются; полное состояние остаётся на вкладках **Before** / **After**.

Если сетевое тело было больше заданного размера события, на вкладке **Body** показывается предупреждение с исходным размером.

### Действия с событием

Действия доступны в меню **⋮** в шапке детализации и в контекстном меню строки (правая кнопка мыши или **⋮** в строке):

| Действие | Назначение |
| -------- | ---------- |
| **Export event** | Экспорт одного события. Для сетевых событий пункт называется **Export request & response**: оба события запроса попадают в один файл |
| **Copy cURL** | Скопировать запрос как команду cURL. Для **Receive response** команда собирается из парного **Send request** |
| **Open request event** / **Open response event** | Перейти к парному сетевому событию |
| **Ignore** | Перестать записывать эту группу событий |

**Ignore** работает по группам: один и тот же запрос (метод и путь), один и тот же компонент, один и тот же стор и т.д. События игнорируемых групп не записываются вовсе; вернуть запись можно в **Options → Logs → Ignore list**.

## Принципы работы

### Когда начинается запись

Запись начинается вместе с остальными модулями Vue Inspector в контексте вкладки. События хранятся на странице, поэтому история доступна, даже если открыть **Logs** позже, без перезагрузки страницы.

### Лимиты

Каждый тип событий — кольцевой буфер: при заполнении самые старые события перезаписываются. Общий бюджет памяти и максимальный размер события обеспечивают стабильность длительных сессий. Значения по умолчанию и настройки описаны в разделе [Настройки логов](./settings.md).

### Маскирование данных

Чувствительные данные маскируются **в момент записи события**, поэтому не попадают ни в интерфейс, ни в экспорт, ни в импорт: пароли, токены, cookies, заголовки авторизации, номера карт и похожие ключи, а также **JWT**, учётные данные **Bearer** / **Basic** и номера карт внутри любого текста.
